## 2. 결함 보고 및 조치 현황 (Defect Tracking)

### [DEFECT-06] [주요(Major)] 판매상태 판매중 공연의 전석 매진 시 S01 공연 목록에 매진 배지 미노출 -> [조치 완료/PASS]
- **관련 요구사항**: PRD AC48("실패: 공연의 모든 등급 잔여수량이 0이거나 판매상태가 매진인 공연 -> 마감 임박이 보이지 않고 매진으로 보인다"), 화면기획서 S01("모든 등급 매진: 공연의 모든 등급 잔여수량이 0 -> 항목에 S01-T3 매진")
- **조치 내용**:
  - `api/src/repositories/eventRepository.ts`의 `findPublicEvents` SQL에서 모든 티켓 등급의 잔여석이 0석인 경우 `is_sold_out: true`를 계산하여 반환하도록 추가.
  - `web/app/page.tsx`에서 `isSoldOut = e.sales_status === "매진" || Boolean(e.is_sold_out)`으로 매진 여부를 정확히 판정하여 S01-T3('매진') 배지를 렌더링하도록 수정.
- **재검증 결과**: TC-UI-35 정상 통과 (PASS).

### [DEFECT-07] [경미(Minor)] 고객 서비스 공통 헤더 링크 문구 불일치 -> [조치 완료/PASS]
- **관련 요구사항**: 화면기획서 S01 문구 표 (S01-T1 | 머리 링크 | 티켓 조회)
- **조치 내용**: `web/components/ui/CustomerHeader.tsx` 14행 문구를 "티켓 확인"에서 화면기획서 표준 문구인 "티켓 조회"로 수정 완료.
- **재검증 결과**: S01-T1 표준 문구 일치 확인 (PASS).

### [기존 조치 완료 내역] (Defect Remediation)

### [DEFECT-01] [치명(Critical)] 현장 QR 입장 확인 시 타 공연 티켓 차단 로직 누락 -> [조치 완료/PASS]
- **조치 내용**: `checkinSchema.ts`에 `event_id` 수신 필드를 추가하고, `checkinService.ts`에서 `order.event_id !== input.event_id`일 때 `409 MISMATCH_EVENT`로 입장을 즉시 차단하도록 로직 반영 완료. 프론트엔드 `checkins/page.tsx`에서도 `MISMATCH_EVENT` 수신 시 S09-T4("입장 불가. 다른 공연의 티켓이에요.") 적색 안내를 렌더링하도록 연동 완료.
- **재검증 결과**: TC-API-34, TC-E2E-07 정상 통과.

### [DEFECT-02] [높음(High)] 백엔드-프론트엔드 간 에러 코드 불일치로 인한 오안내 문구 표시 -> [조치 완료/PASS]
- **조치 내용**: `checkinService.ts`의 결제 미완료 예외 코드를 `INVALID_STATUS`에서 명세서 표준 코드인 `INVALID_ORDER_STATUS`로 변경. 프론트엔드에서 S09-T6("입장 불가. 결제가 완료된 티켓이 아니에요.") 정상 표시.
- **재검증 결과**: TC-API-32, TC-UI-30 정상 통과.

### [DEFECT-03] [보통(Medium)] API 명세서와 백엔드 구현 간 오류 코드 불일치 -> [조치 완료/PASS]
- **조치 내용**: `orderService.ts`, `eventService.ts`, `checkinService.ts` 전반의 오류 코드를 `ORDER_NOT_FOUND`, `ALREADY_PROCESSED`, `TOTAL_LESS_THAN_SOLD`, `INVALID_QR_CODE`로 전면 일치화 완료.
- **재검증 결과**: TC-API-16, TC-API-17, TC-API-29, TC-API-33 정상 통과.

### [DEFECT-04] [보통(Medium)] 운영자 공연 현황 API(`GET /admin/events`) 필수 필드 `end_at` 누락 -> [조치 완료/PASS]
- **조치 내용**: `eventRepository.ts`의 `findAllEventsWithStats` SQL SELECT/GROUP BY 절 및 `eventService.ts`의 반환 DTO에 `end_at`을 추가하여 ISO 8601 문자열로 정상 제공.
- **재검증 결과**: TC-API-24 정상 통과.

### [DEFECT-05] [낮음(Low)] 운영자 공연 현황 API(`GET /admin/events`) 정렬 순서 역순 -> [조치 완료/PASS]
- **조치 내용**: `eventRepository.ts`의 SQL 쿼리를 `ORDER BY e.start_at ASC`로 수정하여 명세 기준 시작일시 빠른 순으로 일치화.
- **재검증 결과**: TC-API-25 정상 통과.
