## 1. 종합 점검 결과 요약

본 보안 엔지니어는 온티켓 서비스의 7대 핵심 보안 영역(SEC-01 ~ SEC-07)에 대해 정적 소스 코드 분석, 아키텍처 경계 검증, 데이터베이스 제약조건 및 트랜잭션 동시성 검토를 전수 수행하였습니다.

온티켓 시스템은 **프론트엔드의 DB 직접 접근 차단, RLS(Row Level Security) 활성화, 서버 독점 결제 금액 및 잔여석 계산, SQL 인젝션 방지(Prepared Statement 100%), 관리자 비밀번호의 메모리 한정 보관** 등 핵심 아키텍처 보안 원칙을 충실히 구현하고 있습니다.

그러나 **1) DB 연결 시 SSL 인증서 검증 무력화(`rejectUnauthorized: false`), 2) 소스 코드 내 테스트 결제 시크릿 하드코딩 폴백, 3) 민감 DB 접속 정보가 담긴 `.dev.vars`의 `.gitignore` 누락, 4) 트랜잭션 내 외부 PG사 API 호출에 따른 커넥션 풀 고갈 위험, 5) 결제대기 건의 재고 점유(Lockup) 무기한 방치, 6) 보안 토큰 및 QR 코드 생성 시 취약한 의사난수(`Math.random()`) 사용** 등 서비스 안정성과 보안에 직결되는 주요 취약점들이 식별되어 개발자 역할의 신속한 개선 조치가 요구됩니다.

## 3. 취약점 상세 분석 및 개선 권고 (Vulnerabilities & Remediations)

본 절에서는 식별된 8건의 취약점(`VULN`) 및 주요 경고(`WARN`)에 대한 파일 위치, 심각도, 취약 시나리오 및 백엔드/프론트엔드 개발자가 적용해야 할 상세 개선 권고를 기술합니다.

### [VULN-01] DB 통신 시 SSL 인증서 검증 무력화 (MITM 공격 노출)
- **점검 영역**: SEC-07 통신 암호화 및 무결성
- **대상 파일**: [`onticket/api/src/lib/db.ts`](file:///home/rokey/ticket_koreatech/onticket/api/src/lib/db.ts#L13) (13행, 34행)
- **심각도**: **High** (CWE-295: Improper Certificate Validation)
- **취약 시나리오**:
  PostgreSQL 클라이언트 생성 시 `ssl: { rejectUnauthorized: false }` 옵션이 설정되어 있습니다. 이 옵션은 DB 서버의 SSL 인증서 유효성을 검증하지 않으므로, API 서버와 Supabase PostgreSQL 간 네트워크 경로에서 ARP 스푸핑, DNS 변조 등을 통한 중간자 공격(MITM)이 발생할 경우 DB 쿼리, 고객 이메일, 주문 데이터, 관리자 비밀번호가 평문으로 도청되거나 변조될 수 있습니다.
- **개발자 개선 권고**:
  운영 및 클라우드 배포 환경에서는 유효한 CA 인증서를 검증하도록 `rejectUnauthorized: true`를 적용하거나, 환경변수(`NODE_ENV === 'production'`)에 따라 엄격한 인증서 검증을 수행하도록 변경해야 합니다.
  ```typescript
  // 개선 권고 예시 (api/src/lib/db.ts)
  const isProd = process.env.NODE_ENV === 'production';
  sqlInstance = postgres(url, {
    max: 10,
    idle_timeout: 20,
    connect_timeout: 10,
    ssl: isProd ? 'require' : { rejectUnauthorized: false },
  });
  ```

### [VULN-05] 미결제(결제대기) 주문의 재고 점유(Lockup) 무기한 방치 (인벤토리 고갈 DoS)

### [VULN-06] 암호학적으로 안전하지 않은 난수(`Math.random()`)를 사용한 QR 코드 생성
- **점검 영역**: SEC-07 통신 및 난수 무결성
- **대상 파일**: [`onticket/api/src/lib/idGenerator.ts`](file:///home/rokey/ticket_koreatech/onticket/api/src/lib/idGenerator.ts#L28-L36) (28~36행)
- **심각도**: **Medium** (CWE-338: Use of Cryptographically Weak PRNG)
- **취약 시나리오**:
  입장 티켓으로 기능하는 QR 코드(`OT-####-XXXX`) 생성 시 `Math.floor(Math.random() * 0x10000)`을 사용하고 있습니다. V8 엔진의 `Math.random()`은 xorshift128+ 기반으로 내부 상태 추정이 가능하며, 토큰 엔트로피가 16진수 4자리(16비트 = 65,536개)에 불과합니다.
  공격자가 해당 공연의 주문번호 패턴(`ORD-YYYYMMDD-####`)을 알고 있을 경우, 현장 검표 API(`POST /admin/checkins`)를 대상으로 무차별 대입 스캔을 수행하여 타인의 티켓 QR을 위조 및 선점 입장할 수 있습니다.
- **개발자 개선 권고**:
  Web Crypto API 또는 Node.js `crypto.getRandomValues()`를 사용하여 암호학적으로 안전한 난수를 생성하고, 엔트로피를 최소 8자리 이상의 16진수(32비트 이상)로 강화해야 합니다.
  ```typescript
  // 개선 권고 예시 (api/src/lib/idGenerator.ts)
  import crypto from 'node:crypto';

  export function generateQrCode(orderId: string): string {
    const digits = orderId.replace(/\D/g, '');
    const last4 = digits.length >= 4 ? digits.slice(-4) : '0001';
    const randomHex = crypto.randomBytes(4).toString('hex').toUpperCase(); // 8자리 hex
    return `OT-${last4}-${randomHex}`;
  }
  ```
